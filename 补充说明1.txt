### 重要补充：项目研究目标与实验设计要求

请特别注意：本项目不仅仅是一个能够自动选择机器学习模型、执行超参数优化的 AutoML Agent，更是一个研究 Agent Tool Runtime、分布式任务编排与可靠执行机制的课程项目。

因此，项目必须同时完成以下两类实验。不能只实现第一类实验，就认为项目已经完成。

#### 实验一：机器学习应用实验（功能验证）

目标：证明 Agent 系统能够真正完成机器学习任务。

具体内容：

1. 用户上传 CSV 数据集，并通过自然语言描述任务需求。
2. Agent 分析数据集，选择合适的 Scikit-learn 模型。
3. Agent 生成实验方案，经用户确认后启动实验。
4. Optuna 自动进行超参数优化。
5. Worker 执行模型训练，输出最优参数和评价指标。
6. Agent 对实验结果进行总结。

覆盖 classification、regression、clustering 和 dimensionality reduction 四类任务。

实验应选择具有代表性的公开数据集，比较默认参数与优化后参数的模型表现。

#### 实验二：分布式执行性能与可靠性实验（核心研究内容）

这是本课程项目必须重点投入的部分。

目标：研究当 Agent 发起多个机器学习实验任务时，如何通过分布式执行、异步任务编排和可靠性机制提高系统吞吐量与任务完成可靠性。

**A. 多 Worker 并行性能实验**

在相同数据集、模型、超参数搜索空间、Trial 总预算和硬件条件下，分别设置：

- 1 Worker
- 2 Workers
- 4 Workers

比较：

- 固定 Trial 数量的总执行时间
- Trial 吞吐量（Trials/min）
- Speedup
- Parallel Efficiency
- CPU、内存资源利用率
- 不同 Worker 数量下的性能瓶颈

使用 Optuna Shared Storage，使多个 Worker 能够连接同一个 Study，自主获取 Trial 并行执行。

如果条件允许，进一步比较同机多进程和跨机器多 Worker 的性能差异。

注意控制实验变量，不能简单地把不同硬件配置下的运行时间直接比较并得出并行加速结论。

**B. 可靠性与容错实验**

设计故障注入实验，验证：

- Tool Timeout：工具调用超时能否正确处理。
- Retry：临时失败后能否安全重试。
- Idempotency：重复提交相同实验请求是否会创建重复 Run。
- Worker Failure：Worker 意外退出后，系统能否识别异常并恢复未完成任务。
- Structured Error：工具是否能够返回明确、可处理的结构化错误。

记录任务成功率、重复任务数量、恢复时间和失败 Trial 数量。

**C. MCP Tool Runtime 实验**

测试 Agent 与 MCP Server 之间的工具调用：

- 工具发现与 Schema 校验。
- 工具调用成功率。
- 平均调用延迟和 P95 延迟。
- 超时和重试行为。
- 不同错误场景下的恢复能力。

区分 MCP 通信开销、Backend 业务处理耗时和模型训练耗时，不要将三者混为一个指标。

#### 三、开发优先级

请按照以下优先级推进：

P0：完成单 Worker 的完整机器学习实验工作流。

P1：实现 PostgreSQL + Optuna Shared Storage + 多 Worker 并行执行，完成 1/2/4 Worker 性能对比。

P2：实现 Timeout、Retry、Idempotency、Worker Failure 等可靠性机制，并完成故障注入实验。

P3：完善 MCP 工具协议、Dashboard 性能监控和实验结果展示。

P4：扩展 PyTorch Adapter、MatPool MCP 等功能。

不要为了尽早实现更多模型或漂亮的 Dashboard，而推迟多 Worker 和可靠性实验。

#### 四、重要要求

从开发初期就为实验二保留必要的性能测量接口，包括：

- Run 创建时间、开始时间和结束时间。
- Trial 创建、开始、完成时间。
- Worker ID、Worker 状态。
- Tool Call 开始与结束时间。
- Timeout、Retry、Failure 事件。
- CPU、内存及可用 GPU 资源指标。

这些数据应当持久化，后续能够导出 CSV 并绘制性能对比图。

最终项目报告必须包含机器学习应用验证、分布式性能分析和可靠性实验三部分。

**请将实验一视为系统的应用基础，将实验二视为课程项目的核心研究贡献。两者缺一不可。**

请先检查目前已有代码和开发进度，尽量在现有架构上增量实现，不要推翻已经完成的工作。
